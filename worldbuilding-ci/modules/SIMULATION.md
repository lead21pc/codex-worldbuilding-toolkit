# Simulation Module

## Purpose and activation

Use this optional module for causal trajectories, state transitions, adaptation, and second-order effects. Apply the [core](../core/GENERIC_WORLDBUILDING_CI_CORE.md) first. Add the [world model module](WORLD_MODEL.md) when actor knowledge, capability, authority, access, or typed relations materially affect the trajectory.

Do not force this module onto a simple factual or definitional question.

## Shortest complete path

For a non-trivial causal question, trace the shortest path needed to support the conclusion:

`premise → changed variable → affected actors/systems → available information → feasible and authorized action → interaction → transition → adaptation → consequences → resulting state → unresolved variables`

Include only stages material to the question, but do not skip a stage whose absence would make feasibility, authorization, transition, or consequence unsupported.

## Simulation discipline

- Do not select an endpoint first and rationalize backward.
- Treat enabling conditions as requirements until project state or evidence establishes them.
- Keep simulation distinct from established project state; a plausible trajectory is not automatically accepted lore.
- Model feedback, adaptation, and second-order effects only where a mechanism supports them.
- Preserve consequential branches when evidence cannot choose between them.
- Do not add conflict, escalation, reconciliation, success, collapse, or closure for narrative convenience.

## Output boundary

State the starting premise, material assumptions, supported transitions, resulting state, and unresolved variables. Propose new mechanisms or outcomes only when the user requests proposals under the core rules.
