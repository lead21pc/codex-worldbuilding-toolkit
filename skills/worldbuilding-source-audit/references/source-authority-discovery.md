# Source-authority discovery

Use this procedure when the project does not already provide an unambiguous source model for the target claim.

## Evidence to inspect

Inspect only the smallest relevant set:

1. The user's explicit scope and any explicit statement about authority for this task.
2. Applicable `AGENTS.md` files and repository instructions.
3. Project documentation describing source roles, publication, continuity, versions, or approvals.
4. Source indexes, manifests, decision logs, provenance records, or equivalent registries.
5. Repository structure and the source files themselves.

The list is a discovery route, not a universal precedence order. When two instructions appear to disagree, report the conflict and use only precedence rules actually supplied by the user, environment, or project.

## Build a local source model

Record only categories the project establishes or evidence supports:

| Question | Evidence to record |
| --- | --- |
| What sources can establish world facts? | Project rule and location |
| Does authority vary by topic, era, continuity, viewpoint, or edition? | Scope rule and affected sources |
| Which materials are provisional, drafts, notes, deprecated, or historical? | Project term and status evidence |
| Are any files derived or generated? | Inputs, outputs, and documented transformation |
| How does replacement or supersession work? | Decision record or project rule |
| Which invariants must remain true? | Exact declared invariant and scope |
| Who or what can approve changes? | Explicit project or user instruction |

Do not require a project to use words such as "canon," "official," or "draft." Preserve its own terminology and define unfamiliar terms in the audit report.

## Authority is not inferred from appearance

None of these facts establishes authority by itself:

- filename, directory position, or naming conventions;
- modification time or version number;
- inclusion in an archive or generated package;
- polished prose or apparent completeness;
- repetition across derivative files;
- a model's expectation about how worldbuilding projects usually work.

Generated output may be authoritative, derivative, or merely convenient. An archived source may remain controlling, be historical only, or have no declared status. Determine the role from project evidence.

## Unresolved authority

If no rule establishes precedence:

1. List the sources and the claims each one supports.
2. Describe agreements and differences without selecting a winner.
3. Mark authority as unresolved for the affected scope.
4. Ask for a decision only when a definitive conclusion or source modification requires one.

Evidence collection can continue. Do not convert uncertainty into an invented hierarchy.
